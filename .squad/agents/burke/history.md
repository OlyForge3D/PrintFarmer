### H1a — Migration script duplicate DECLARE (Hicks primary)
- **Problem:** `dotnet ef migrations script` concatenates every `migrationBuilder.Sql()` into one GO batch; the r6/r7 `OnlineAwareCreateUniqueIndex` helper emitted `DECLARE @online`/`DECLARE @sql` per call → repeated declares in a single batch → **Msg 134** under script-based deploy flows (SQLCMD/sqlpackage). `database update` masked it (separate IDbCommands).
- **Fix:** `20260713235657_...cs` `OnlineAwareCreateUniqueIndex` — unique variable names suffixed with the index name (`@online_{indexName}`, `@sql_{indexName}`). Kept Frost r6 BIN2 + Newt r7 WITH NOCHECK + EngineEdition ONLINE detection intact.
- **Task "Option A" (inline `EXEC('...' + CASE ... + '...')`) rejected:** `EXEC()` only accepts string literals + string variables as `+` operands — CASE/function calls are rejected grammar. Used variable-based dynamic SQL (Option C style: unique-named vars) instead.

### H1b — Down migration hardcoded CI_AS collation (Hicks secondary; Bishop non-blocking → now a gate)
- **Problem:** Down() `ALTER COLUMN ... COLLATE SQL_Latin1_General_CP1_CI_AS` assumed the server default catalog collation. On DBs with a different catalog collation, rollback silently re-collated to the WRONG collation.
- **Fix:** new `RevertCollationToCatalogDefault` helper (added to both migration classes) emits dynamic SQL reading `DATABASEPROPERTYEX(DB_NAME(),'Collation')` into a uniquely-named `@coll_{table}_{column}` var, then `ALTER COLUMN ... COLLATE ' + @coll_... `. Applied to all 4 reverts in `20260713235657_...` Down() (HarvestOperationKey, OperationKey, Sku, Code) and the 3 reverts in `20260713163813_...` Down() (UserId, RouteKey, IdempotencyKey).
- **Batch-scoping note:** T-SQL variables are batch-scoped, not block-scoped — H1a index-name suffixes (`IX_*`) and H1b `{table}_{column}` suffixes never collide within a shared GO batch (proven: down-script batch #0 has 12 distinct DECLAREs).

## Learnings

- `dotnet ef migrations script` needs FULL migration names, not bare IDs (bare IDs → "migration not found"). FROM is exclusive, TO inclusive; `0` = empty DB.
- `EXEC('literal' + expr)` grammar: only literals + string vars concatenate; CASE/functions must be assigned to a variable first, then `EXEC sys.sp_executesql @var`.
- T-SQL local variables are batch-scoped; BEGIN/END does NOT isolate them. Unique per-invocation variable names are the reliable way to keep repeated `migrationBuilder.Sql()` helpers script-safe.
- `has-pending-model-changes` compares model snapshot vs live model and never evaluates Down() — Down() edits + Up() helper refactors that don't touch the model stay clean on both providers.
- ASP.NET Core validates DataAnnotations on positional record (constructor) parameters, so a `[ReservedOperationKeyPrefix]` on a DTO record param genuinely fires at the API boundary (no manual `TryValidateObject` needed).
