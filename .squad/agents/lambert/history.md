## Learnings

- **2026-05-26 — Klipper online/offline classification.** Moonraker/Klipper live status for the printer list flows through `MoonrakerSubscriptionService` into `PrinterStatusCache`, then `PrintersService.GetAllCompleteDtosAsync` serves the cached `IsOnline` to web and iOS clients. Root cause for false offline was that `_klippyReadyState` only initialized from `webhooks.state`; some valid subscription/status payloads contain printer objects without `webhooks`, so reachable printers such as `arco1` could keep broadcasting `IsOnline=false`. Fix pattern: classify explicit `webhooks.state != ready` as not-ready, but treat successful printer-object status as proof of reachability; also update the cache during HTTP fallback and shutdown broadcasts so REST clients do not read stale offline/online state.

- **2026-05-26 — Camera endpoint detection API.** Added `IPrinterCameraProbe` in the discovery layer with `PrinterCameraEndpointDetectionService` selecting probes by `Printer.Backend`. Concrete probes now exist for Moonraker/Klipper (`source: "klipper"`, using Moonraker configured webcam detection), OctoPrint (conventional `/webcam/?action=stream|snapshot` URLs), and SDCP/Elegoo (HTTP `/video` + `/snapshot` probes through the SDCP camera capability). Unsupported or failed probes return `{ detected: false }`, never a probe 500. `CameraDto` now includes `printerId` and `printerName` for list/get/update responses; `UpdateCameraDto.PrinterId` remains optional and only changes association when a non-null ID is supplied.

- **2026-05-21 — Active-printing state set must match PrinterControlGate semantics (issue #309, PR #310).** `PrintFailureMonitorService.EvaluateMonitoringWindow` had an exact-match `status.State == "Printing"` check while `PrinterControlGate.BusyStates` had long since broadened to `{Printing, Pausing, Paused, Resuming, Cancelling, Heating}`. Result: the spaghetti-detection shield falsely told users their actively-printing printer was idle whenever the printer reported `Paused/Heating/Pausing/Resuming`. Fix: extracted `Farm.Infrastructure.Services.Printers.PrinterStateClassifier.IsActivePrintingJob(string?)` covering `{Printing, Heating, Pausing, Paused, Resuming}` (case-insensitive, whitespace-tolerant) and used it from `EvaluateMonitoringWindow`. Set is intentionally **narrower** than `PrinterControlGate.BusyStates` — drops `Cancelling` because AI-monitoring a print that is being aborted is wasted work. The two domains (failure detection vs user-command gating) are allowed to diverge, but the classifier centralizes the canonical set so the divergence is visible in one file. Pattern: any string-based state predicate scattered across services is a future bug — prefer a small classifier helper near whichever module owns the canonical set. Out of scope (follow-up): idle-reason copy taxonomy so the shield doesn't say "not printing" when the real reason is "backend doesn't support detection".

- **2025-11-22 — PrintersService MMU gate semantics (issue #302, PR #303).** `mmuGateCount` parameter on `CreateMmuVirtualToolheads` / `SyncMmuVirtualToolheads` / `SyncMmuToolheadsOnEntity` means **total number of AMS gates**, NOT a strict upper-bound index. Loop must be `for (int i = 1; i <= mmuGateCount; i++)` to produce N gates at indices 1..N (T0 reserved for Physical hotend). Companion helpers `SetToolheadSpoolAsync` / `ClearToolheadSpoolAsync` use `Math.Max(4, toolheadIndex)` (no `+1`) — index N maps directly to a count-of-N. Bambu defaults to `mmuGateCount = 4`. Existing data already seeded under the old `<` bound is **not** auto-repaired — backfill needs a separate hosted service or migration.

- **2026-05-26 — Login audit log implementation.** New `LoginAuditEntry` entity (separate from `AuthAuditLog`/`IAuthAuditService`) with `Username` as a direct indexed column for efficient admin querying. `AuthController.LoginAsync` is the hook point — inject `ILoginAuditService` there (NOT into `AuthenticationService`). `ResolveClientIp` static helper: check `X-Forwarded-For` first (leftmost entry), fall back to `HttpContext.Connection.RemoteIpAddress`. `MapFailureReason` maps the opaque error string returned by `AuthenticationService.AuthenticateAsync` to normalized codes (`account_locked`, `account_disabled`, `invalid_credentials`). - **2025-12-09 — Issue #290 backend capability guards.** `/api/printers/{id}/temps|move|moveto` now gate on cached printer state via `PrinterControlGate.IsBusyForControl({Printing,Pausing,Paused,Resuming,Cancelling,Heating})` and return 409 `CommandResult { Success=false, Message="Printer is currently {state}." }` before the service is ever called. ## Learnings — 2026-05-28

### Gate pattern reused for home endpoints (#314, PR #316)

The `GatePrinterControlAsync` + `MapControlOutcome` pattern in `PrintersController` is the canonical way to add status-gated control to any printer endpoint. Pattern lives at lines ~2122–2155. The three home handlers (`/home`, `/homexy`, `/homez`) previously returned `bool` from service methods — gate sits in front and short-circuits with 409 before the service call; the `bool` result mapping stays unchanged after the gate.

### Plugin-propagation gap deferred (follow-up #317)

Moonraker, SDCP, and FlashForge plugins do not translate firmware busy responses into `PrinterBackendBusyException`. This was confirmed in the #279 spike. The controller gate is sufficient as the primary defense; the race-condition gap (firmware refuses between gate check and call) is tracked as P2 in issue #317.

### Test pattern: unit mock controller tests, not CustomWebApplicationFactory

For guarded-endpoint coverage, the existing `PrintersControllerControlGuardsTests` uses a direct `new PrintersController(...)` with Moq — not `CustomWebApplicationFactory`. This keeps the tests fast and focused. Mirror this for any future control-guard additions.
