## Implementation Details

### Service Design
- Server pooling with enabled/disabled state
- Concurrency hints via `MaxConcurrentAnalyses` (stored, enforcement deferred)
- Health endpoint tests connectivity with latency measurement
- Delete operation validates no active assignments before removal

### Backward Compatibility
- Global `ObicoSettings.ObicoApiUrl` remains unchanged
- Printers with null `ObicoServerId` use global default
- Explicit assignment overrides global setting
- Existing deployments work without configuration changes

### Error Handling
- 404 when server not found
- 409 when deleting server with assigned printers (with affected count)
- 500 with descriptive message on health check failure
- Service-layer validation prevents orphaned printer references

## Key Design Decisions

### 1. Per-Printer Assignment vs Global Pool
- **Chosen:** Per-printer with global fallback
- **Rationale:** Gives users explicit control, maintains backward compatibility
- **Future:** Automatic load balancing with capacity awareness

### 2. Delete Validation
- **Chosen:** Block deletion if printers assigned (soft safety)
- **Alternative:** Cascade to null (considered too aggressive)
- **Safety:** Prevents accidental orphaning

### 3. Health Check Mechanism
- **Chosen:** HEAD request to server's `/p/` endpoint
- **Rationale:** Minimal bandwidth, non-intrusive, detects connectivity
- **Result:** Includes latency measurement for server comparison
