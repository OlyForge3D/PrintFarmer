## Work Completed

### Deployment Profile Selection in install.sh

**Objective:** Add flexible deployment profile options (lite/standard/full) to support heterogeneous deployments from Raspberry Pi to production.

**Deliverables:**

1. **CLI Flag & Interactive Menu**
   - Added `--profile lite|standard|full` to install.sh
   - Interactive numbered menu (1/2/3) when no flag provided
   - ARM auto-detection pre-selects lite profile
   - Backward compatible: no flag defaults to standard on non-ARM systems

2. **Profile → Infrastructure Mapping**
   - **Lite:** Monolith (1 container, SQLite locked, port 5000)
   - **Standard:** Microservices (3 containers: api + frontend + nginx, SQLite by default, port 80)
   - **Full:** Extended services (7 containers: microservices + PostgreSQL + discovery + monitoring)

3. **Configuration Management**
   - `DEPLOY_PROFILE` stored in `.env` for upgrade awareness
   - `DB_EXPLICIT` flag prevents profile override of user-specified database
   - Interactive database prompt skipped for lite (forced SQLite) and full (defaults PostgreSQL)

4. **Compose Generation**
   - All three profiles generate inline (self-contained installer)
   - No external compose templates required during install
   - Health check logic adapts to profile (monolith vs api container name)

## Technical Decisions

| Decision | Rationale |
|----------|-----------|
| Inline compose generation | Self-contained installer, no repo clone needed for end users |
| ARM auto-detection | Raspberry Pi 4 is deployment sweet spot; lite profile is best fit |
| DB_EXPLICIT flag | Respect explicit `--db` choice despite profile defaults |
| Profile in .env | Future upgrades know active profile, avoid config drift |
| Skip nginx for lite | Monolith serves directly on port 5000; no reverse proxy needed |
