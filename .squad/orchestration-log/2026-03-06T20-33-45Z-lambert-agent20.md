## Mission
Implement Auto-Dispatch Phase 2: event-driven background service for intelligent job auto-assignment on printer idle.

## Deliverables

### Entities & Schema Changes
- **DispatchSettings** (singleton): AutoDispatchEnabled, AutoDispatchMode (Manual/Suggest/Auto), IdleThresholdSeconds, MinimumScoreThreshold, MaxConcurrentDispatches
- **DispatchLog** audit trail entity for all dispatch actions

### Core Architecture
- **AutoDispatchTrigger** (singleton) — Channel-based event sink, fire-and-forget from scoped services
- **AutoDispatchBackgroundService** (IHostedService) — Event-driven consumer with per-printer idle timeout and CancellationTokenSource
- **Thread safety via SemaphoreSlim(1,1)** — Prevents simultaneous dispatch decisions for overlapping idle windows
- **Interlocked counter** — Enforces MaxConcurrentDispatches limit

### API Endpoints
- `GET /api/dispatch-settings` — Retrieve current settings
- `PUT /api/dispatch-settings` — Update settings with validation

### SignalR Events
- `jobautodispatched` — Auto mode assigned job to printer
- `dispatchsuggestion` — Suggest mode requires operator decision
- `dispatchfailed` — Dispatch operation failed

### Service Layer Integration
- `PrintJobCompletionService` hook: NotifyPrinterIdle(printerId) after job completion
- Scoring reuse: No duplication, leverages `IDispatchScorer.ScorePrintersForJobAsync()`
- Suggest mode: Emits SignalR event, logs as "Suggested", does NOT dispatch
- Auto mode: Auto-dispatches, logs as "Auto", emits success event

## Key Decisions
1. **Event-driven via Channel** — No polling, no background job queue dependency
2. **Per-printer cancellation** — CTS allows canceling pending dispatch if printer goes offline/disabled
3. **Singleton DispatchSettings** — Configuration persisted to DB, updated via API
4. **Suggest + Auto modes** — User choice: notifications only (Suggest) vs full automation (Auto)
