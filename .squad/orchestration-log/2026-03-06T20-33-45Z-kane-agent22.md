## Critical Patterns Discovered

### Component Structure
- **LocationManagement renders PrinterLocationDragDrop internally** — must mock DragDrop when testing LocationManagement in isolation

### Testing Challenges
- **Button text in spans** — use `getAllByRole('button', { name: 'X' })` instead of `getAllByText`
- **Tree table dual text** — location names in both Name + Path columns cause `getByText` ambiguity
- **PrinterCard property mismatch** — uses `printer.backendUrl` but interface has `serverUrl` (renders undefined)

### Mocking Pattern
- **Dynamic mock imports** — use `await import('@/services/locationService')` for accessing mocked functions after `vi.mock`
- **ConfirmationModal** renders inline (no portal) — works fine with `waitFor`

## Test Infrastructure
- All tests use Vitest + React Testing Library
- Queries favor accessible patterns (getByRole, getByLabelText)
- User interactions via `userEvent` for realistic behavior
- Async operations wrapped in `waitFor` with timeout
