## Architecture Decisions

### Component Design Pattern

**PrintProgressBar Props:**
- **Required:** `progress: number | undefined`, `jobName: string | undefined | null`, `isActive: boolean`
- **Optional:** `progressRef?: React.RefObject<HTMLDivElement>`, `showInactiveState?: boolean`, `showTemperatures?: boolean`
- **Temperature props:** hotendTemp, bedTemp, hotendTarget, bedTarget, isOnline (only if `showTemperatures=true`)

**Key Design Choices:**

1. **Layout Stability:** Non-breaking space (`\u00A0`) fallback when no job name exists prevents layout shift in DetailedPrinterCard
2. **Outer Spacing:** Component excludes margin; parent cards apply wrapper margin (`mt-2`, `mb-4`) for composability
3. **Progress Clamping:** Always clamps 0-100: `Math.max(0, Math.min(100, progress))`
4. **Accessibility:** Full ARIA progressbar implementation (`role="progressbar"`, `aria-label`, `aria-valuemin/max/now`, `sr-only` text)
5. **Temperature Indicators:** NozzleIcon `isOn` when hotend > 50°C; BedIcon `isOn` when bed > 35°C

### Bug Fix

**DetailedPrinterCard 0% Bug:**
- **Issue:** `progress > 0` condition prevented progress bar display when print just started (0%)
- **Solution:** Removed condition in PrintProgressBar; relies on `isActive` boolean instead
- **Impact:** Progress bar now correctly shows 0% when print begins

## Known Patterns

When extracting shared components:
1. Use optional boolean flags for behavioral differences (`showInactiveState`, `showTemperatures`)
2. Keep outer spacing/margin with parent components, not in shared component
3. Preserve exact layout behavior (like `\u00A0` fallbacks) during refactoring
4. Always forward refs when parent needs to access child DOM elements
5. Include comprehensive ARIA attributes for accessibility
