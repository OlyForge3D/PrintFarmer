# pfdev No Longer Generates docker-compose.yml

## Decision

The `pfdev` script must NOT generate or refresh `docker-compose.yml`. Only `./scripts/deploy-docker.sh` should generate this file.

## Context

User reported: "the only thing that should be generating docker-compose.yml is deploy-docker.sh"

Previously, `pfdev` had `ensure_generated_stack()` function that would:
- Check if docker-compose.yml was outdated relative to compose templates
- Automatically regenerate it by calling compose-generator.sh
- Do this on every `pfdev build` and `pfdev deploy` operation

This caused problems:
1. Unpredictable overwrites of user's deployment configuration
2. Confusion about which script controls what
3. Connection string issues when pfdev regenerated compose with different settings than deploy-docker.sh used

## Implementation

**Removed:**
- `generated_stack_needs_refresh()` function (93 lines of compose staleness detection)
- `ensure_generated_stack()` function (called compose-generator.sh)
- `COMPOSE_GENERATOR` variable
- All compose generation logic

**Added:**
- `check_required_files()` function that validates required files exist
- Fails loudly if docker-compose.yml, Dockerfile.multistage, or docker-entrypoint-config.sh are missing
- Clear error message pointing users to `./scripts/deploy-docker.sh`

**Preserved:**
- TLS certificate refresh logic (`ensure_tls_certificates()`) — still needed for nginx/frontend
- Service alias mappings (nginx → nginx-proxy)
- All build/deploy functionality

## Error Message Pattern

When required generated files are missing, pfdev now shows:

```
❌ Required generated files are missing:
   - docker-compose.yml
   - Dockerfile.multistage

These files are generated by the deployment script.
Run: ./scripts/deploy-docker.sh
```

This is clearer than the old behavior of silently regenerating files with potentially different settings.

## Benefits

1. **Single source of truth:** Only deploy-docker.sh generates compose files
2. **Predictable behavior:** pfdev never modifies deployment configuration
3. **Clearer workflows:** User knows exactly what each script does
4. **Fail-fast:** Missing files cause immediate, helpful errors
5. **No silent overwrites:** User's deploy configuration is never lost

## Workflow

**Correct workflow:**
1. `./scripts/deploy-docker.sh` → generates docker-compose.yml + .deploy-config
2. `pfdev redeploy api` → uses existing docker-compose.yml (fails if missing)

**Incorrect workflow (now prevented):**
1. `pfdev redeploy api` → ERROR: "Run ./scripts/deploy-docker.sh first"

## Related Files

- `scripts/pfdev` — developer CLI for fast rebuilds
- `scripts/deploy-docker.sh` — full deployment with compose generation
- `scripts/docker/compose-generator.sh` — compose file assembler
- `.deploy-config` — deployment settings (source of truth for deploy-docker.sh)
